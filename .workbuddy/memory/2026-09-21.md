## bat 无法运行修复（同一天，第三轮）

用户反馈「bat 没法运行」。排查结论：

- **根因 = 换行符**。上一轮用 Write 工具新建/改写的 bat **全部落盘为 LF（Unix）换行**；
  cmd 解析批处理是**按字节偏移定位**的，LF-only 的 bat **双击后完全无输出、直接闪退**。
  对照实验（同一份内容，LF vs CRLF 两份文件）证实：**LF 版零输出，CRLF 版正常**。
- 原本就存在的 `weixin-auto\start_all.bat`、`AudioDeDupTool\开始.bat` 是 CRLF，所以一直没事 ——
  只有我新建的那些中招，这也解释了为什么用户觉得"以前好好的"。

**修复**：全盘扫描（`E:\` 递归，排除 `.venv`/`node_modules`/`_归档`/`_backup`/`_probe_tmp`），
按**字节级**做 LF→CRLF（不动编码，避免破中文），共修 **12 个**；
备份在 `weixin-auto\_probe_tmp\_bat_backup_20260921\`：

```
E:\_一键装齐依赖.bat
weixin-auto\{启动, start_editor}.bat
```

### 本轮新坑 / 纠正
- **`cmd` 其实能用**：`& "$env:COMSPEC" /c "xxx.bat"` 实测可用（上一轮记为"被禁用"不准确）。
  但安全策略会拦**命令文本里含 `>nul`、`%VAR%` 字面量**的写法 → 脚本里去掉这些字面量即可（用 `& $env:COMSPEC` 代替 `cmd`）。
- **捕获 cmd 输出前必须先 `[Console]::OutputEncoding=[Text.Encoding]::UTF8`**，
  否则 UTF-8 编码的 bat 中文看起来全是乱码，极易误判成 bat 自身有问题（第一次就踩了）。
- **编码惯例**：本盘原有 bat 是 **GBK 无 chcp**（依赖系统 936）；新建的用 **UTF-8 无 BOM + 第 2 行 `chcp 65001`**。
  两种都正常，**别混**。
- `AudioDeDupTool\鍋滄.bat`（1101B）是历史遗留的**乱码文件名**文件，与正常的 `停止.bat`（1201B）重复，
  由该目录里的 `_write_bats.ps1` 生成，**不是本轮产物**；未擅自删除，留给用户决定。
- `E:\挽回聊天工具`、`E:\抖音聊天界面`、`E:\video-factory` 顶层**没有任何 bat 启动入口**（前者靠 `切片工具\长图模式\wx_pipeline.py`）。
