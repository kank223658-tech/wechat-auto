## 修复：工作流运行报错 Page.goto Timeout

- 现象：`Page.goto: Timeout 10000ms exceeded`（navigating to `http://localhost:8080/#/#/`），
  随后「逐帧合成出现问题：跳过加载期后没有帧」。
- 根因：`ensure_frontend_running()` 只判断端口监听；Vite dev server 端口开得快、首页要按需编译，
  于是 Playwright 用默认 10s 打开页面时超时。
- 修复（`main.py`）：
  - 新增 `_frontend_http_ready()` / `_wait_frontend_ready()`：真正 GET 一次首页，拿到 HTTP 响应才算就绪。
  - `ensure_frontend_running()`：端口已监听时也等首页可访问；自动启动分支端口就绪后继续等首页编译完。
  - `page.goto(BASE_URL)` → 90s 超时 + 失败重试（重试前等首页就绪）；
    store 就绪的 `wait_for_function` 超时 10s → 20s。
- 实测（冷启动、无前端在跑）：全流程跑通，产出 `videos/wx_20260910_210530_076.mp4`（6.7 MB），
  首帧即场景主页「微信 (9)」，7 步动作全部成功。

### 验证方法论（本环境很重要，跨会话复用）
- 本模型**读不了图片**（Read 返回 “Content filtered”）。视觉验证三件套：
  1. **PIL+numpy 像素采样**：行/列均值、亮度带 bbox、std（判断画面是否有内容）。
  2. **ASCII 灰度图**：`Image.resize((w,h))` 后用 `" .:-=+*#%@"` 逐像素打印 —— 能直接「看懂」画面布局。
  3. **冻结关闭动作**：动作结尾会主动关掉播放器/查看器，导致事后探测永远是 false。
     在页面里把 `__wxVideo.close` / `__wxMoments.closeImage` / `__wxHuman.closeImage` 临时换成空函数
     （`PATCH_ON`），动作结束后就能观测到真实打开状态，再 `PATCH_OFF` 还原并真关。
- 后台服务要注意：Bash 工具里 `nohup ... &` 起的进程**会在工具调用结束后被回收**，
  必须用 `run_in_background=true`；结束时用 `netstat -ano | grep :端口` 找 PID 再
  `taskkill /PID <pid> /F`（注意 Git Bash 下写 `//PID` 会被 taskkill 拒绝，改用 python subprocess 传参）。
