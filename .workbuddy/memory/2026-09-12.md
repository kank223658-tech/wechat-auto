## 掉帧问题架构分析（20:14，只分析未改码）
- 用户问实时录制掉帧还能怎么办（曾试虚拟时钟失败）。梳理链路后给出结论：掉帧分三类——A 结构性（同步 Playwright 事件只在调用期间派发，Python 侧任何 CPU/IO 都停帧流）、B 管道性（screencast 一帧一 ack，ack 延迟→浏览器丢中间帧）、C 系统级（合成器被节流 0.3-0.5s，flag 已挡遮挡类，剩 CPU 降频/Defender）。
- 虚拟时钟失败原理：setVirtualTimePolicy 只控 renderer 时钟不控合成器 vsync，screencast 帧来自合成器，两者错位。
- 给出的建议排序：①录制质量守门员+自动重录（帧间隔直方图，剧本内容重录成本低，最快落地）；②独立 CDP websocket 采集线程（绕开 Playwright 事件派发依赖，sync API 非线程安全的折中解）；③转场段确定性重采：触发后 `document.getAnimations()` 全 pause → 逐帧设 currentTime+截图，与已有 hard_cut_spans 窗口机制契合；④剩余缺口用 minterpolate/RIFE 光流插帧替代 crossfade；⑤系统清单：高性能电源计划、Defender 排除 profile/临时目录。
- 长期选项：迁 Playwright async API 或前端导演时钟（动画由可注入时钟驱动，才是"真虚拟时钟"）。
